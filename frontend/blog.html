01 · My Journey

From NIELIT O Level to becoming an AI developer

My story started in Pundri, Kaithal — a small town where computers felt like magic. I finished my Class 10th in 2023 and Class 12th in 2024, and somewhere in between I realised that technology wasn't just a subject, it was a language I wanted to speak fluently.

The technical foundation — NIELIT O Level

After school I completed the NIELIT O Level — a government-issued, recognised certificate from the National Institute of Electronics & Information Technology. This was my real induction into programming. It gave me solid, structured foundations in:

HTMLCSSJavaScriptPythonC++IoT

Unlike quick YouTube tutorials, O Level pushed me through assignments, practicals and theory. That discipline is what I still rely on — I don't just watch code, I build. You can see the result of that training in my live web development projects and the full list of technical skills I've built since.

The software developer upgrade

Once the fundamentals were in place, I went deeper on my own. I taught myself modern front-end development with React + Vite, moved into the back end with Node.js + Express, and learned to manage versions and workflows with GitHub. I deploy my sites through Vercel and Render, so everything I build actually goes live.

And then came AI

AI changed everything for me. Instead of just using tools, I started building with them — training myself in ChatGPT, Gemini and Claude workflows, and eventually building my very own chatbot using AI models (you can read exactly how below). Today I call myself an AI developer not because I use AI, but because I integrate AI into real products.

How I built my own chatbot — step by step

Building a chatbot taught me more than any course. This is the exact process I followed:

  1. Defined its purpose. I decided what my chatbot should do — answer questions about me, my skills and my work, like a smart digital assistant.
  2. Picked the AI brain. I connected the chatbot to a large language model using an API, so it could understand and reply naturally instead of using pre-written answers.
  3. Wrote the instructions (system prompt). This is the secret step — I gave the model a clear personality, tone and boundaries so answers stay helpful and on-brand.
  4. Built the chat interface. Using HTML, CSS and JavaScript I designed a friendly chat window with a message bubble layout, typing states and a clean mobile layout.
  5. Connected the back end. A small Node.js + Express server takes each user message, sends it to the AI model, and returns the reply — safely, without exposing any keys.
  6. Tested and refined. I asked it tricky questions, fixed responses that felt robotic, and polished how errors and empty states are handled.
  7. Deployed it. I pushed the code to GitHub and deployed the bot so it runs live for anyone to use.

03 · Web Development

My full-stack process — from idea to live website

My tech stack

HTMLCSSJavaScript ReactViteNode.jsExpress GitHubVercelRender

I build responsive, fast-loading websites. I use vanilla HTML/CSS/JS when a project needs to be lightweight and instant, and move to React + Vite when a site needs real interactivity and reusable components. For anything that needs a database or an API, I write the back end in Node.js + Express.

How I actually build and ship a website

  1. Clarify the goal. What is the site for? Who visits it? What action should they take? I answer these before writing a single tag.
  2. Plan the structure. I map out pages, sections and a clear content hierarchy — this also becomes the SEO skeleton.
  3. Design the experience. I design with colour, typography and spacing in mind so the site feels cohesive and modern.
  4. Build responsive HTML & CSS. Mobile-first, semantic tags, accessible and fast-loading.
  5. Bring it alive with JavaScript. Interactions, animations, forms and dynamic content.
  6. Add quality checks. I test on mobile, tablet and desktop, check performance and fix broken links.
  7. Deploy through GitHub + Vercel/Render. I push code to GitHub, then deploy — every update goes live cleanly.

This exact pipeline powers my portfolio, my school website projects and the full-stack admin systems I build for clients — one consistent, repeatable way to go from idea → code → live URL. One of the first sites I shipped this way is the Anjali Kids School website, a responsive school site built with HTML, CSS and JavaScript.

06 · SEO

Getting found on Google

On-page SEO fundamentals

On-page SEO is where ranking actually lives. Every page I optimise gets a unique title tag (under 60 characters), a meta description (150–160 characters) that makes people want to click, and a logical heading structure — one H1 per page, with H2s and H3s organising the content the way Google expects.

Keyword placement that works

I place primary keywords where they matter most — in the title, the first paragraph, headings and image alt text — without stuffing. The goal is natural language that both humans and search engines understand clearly.

Content depth over content length

Ranking isn't about word count; it's about whether a page fully answers what someone searched for. I write complete, structured content that covers a topic thoroughly, with headings, lists and examples — so visitors leave satisfied and search engines treat the page as an authority.

Technical SEO basics

I apply the fundamentals behind the scenes too: semantic HTML5 tags (<header>, <main>, <article>, <footer>), fast-loading code, mobile-first responsive design, clean links, and structured data (JSON-LD) so search engines understand who the page is about.

Local SEO for Kaithal & Haryana

For offline businesses the win is local. I use location-based keywords like "best web developer in Kaithal", optimise Google Business Profile listings, encourage local reviews, and make sure Name, Address and Phone details are consistent across the web. For Pundri, Kaithal and all of Haryana, this is how a small business shows up when people nearby search for it.
